# CLI, HTTP и перенос

[English](interfaces.md) · [Русский](interfaces.ru.md) · [README](../README.ru.md)

`buro <id-or-name>` получает запись; `buro get <id-or-name>` также работает с id,
совпадающими с командами CLI. Точный id имеет приоритет. Неоднозначное имя
показывает варианты id. `buro search <text>` ищет по id, именам и алиасам;
`buro list [kind]` выдаёт идентификаторы. По умолчанию возвращается 100 записей;
доступны `--limit 1..1000` и `--offset`. Полная страница показывает подсказку
для следующей.

`buro types [kind]` показывает определения; `schema` сохраняется для совместимости.
`buro types copy <built-in> <file>` копирует готовый YAML. `buro current --brief`
получает необязательные правила машины, `buro current` — ещё до 100 записей с
местоположением на ней. Отсутствующая запись хоста — нормальный результат.
`init --dry-run` проверяет применение, `init` применяет. `agent`, `agent --full`
и `connect` обеспечивают [подключение агента](agents.ru.md).
Обычные изменения идут через [черновик](draft-workflow.ru.md).

## HTTP

`buro serve --host 127.0.0.1 --port 8765` открывает применённую локальную модель.

| Маршрут | Назначение |
| --- | --- |
| `GET /health` | Состояние базы и модели |
| `GET /schema` | Нормализованные определения с полями каждого типа |
| `GET /entities` | Все записи для явного администрирования |
| `GET /entities?summary=1&kind=project&q=site&limit=100&offset=0` | Страница идентификаторов; тип и запрос необязательны |
| `GET /current?current_context=worker&brief=1` | Пакет машины; brief не загружает связанные записи |
| `GET /entities/:id` | Запись по id, имени или алиасу |
| `GET /packet/entity/:id?current_context=worker` | Структурированный пакет |
| `POST /entities/:id?current_context=worker` | Создание с машиной пишущего клиента |
| `PUT /entities/:id?current_context=worker` | Замена с версией `If-Match` |
| `DELETE /entities/:id` | Удаление с версией `If-Match` |

`current_context` обозначает машину, а не обязательную запись хоста. CLI
передаёт её при записи, поэтому путь клиента не приписывается серверу.
Лимит тела — 1 MiB. Клиент ждёт три секунды без автоматического повтора.
Сервер не содержит авторизации и TLS: используйте loopback, доверенную частную
сеть или защищённый proxy.

## Экспорт и восстановление

`buro export <file>` создаёт детерминированный YAML с правами 0600: записи,
версии и применённая модель. Экспорт v2 включает определения без путей исходных
конфигов. `buro import <file> [--adopt]` проверяет все записи и ссылки перед
заменой в одной транзакции. Непустая база сохраняется в снимке. Экспорт v1
поддерживается, включая известные миграции с `--adopt`.

Для восстановления своей конфигурации выберите соответствующие определения;
объект `model` из экспорта также пригоден как полный YAML для `schema_path`.
`--adopt` разрешает другую привязку, но не удаление несовместимых полей.
Экспорт и импорт требуют локального хранилища; клиенты не копируют центральную базу.
