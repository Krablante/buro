# Интерфейсы

[English](interfaces.md) · [Русский](interfaces.ru.md) · [README](../README.ru.md)

Основные команды чтения: `buro <id>`, `buro current`, `buro list [kind]` и
`buro schema [kind]`. Точный id имеет приоритет перед алиасом. `current`
находит настроенный контекст и перечисляет записи, чьё поле связи указывает
на него; это срез реестра, а не общий список. `buro --version` показывает
версию установленного пакета. Обычная запись идёт через
[черновик](draft-workflow.ru.md).

## HTTP для клиентов

На центральном экземпляре запусти `buro serve --host 127.0.0.1 --port
8765`. Сервер работает с тем же resolver и той же базой, что и локальный
CLI.

| Маршрут | Смысл |
| --- | --- |
| `GET /health` | Состояние базы и активного пресета |
| `GET /schema` | Пресет для проверки клиентского черновика |
| `GET /entities` | Полный JSON всех записей для администрирования или экспорта |
| `GET /entities?summary=1&kind=host&current_context=worker` | Краткий список и id текущего контекста; `kind` необязателен |
| `GET /current?current_context=worker` | Id/корень контекста, пакет и краткий список его сущностей |
| `GET /entities/:id` | Одна сущность с поддержкой алиасов контекста |
| `POST /entities/:id` | Создать сущность |
| `PUT /entities/:id` | Изменить с версией в `If-Match` |
| `DELETE /entities/:id` | Удалить с версией в `If-Match` |
| `GET /packet/entity/:id?current_context=worker` | Структурированный пакет с пояснениями |

Клиентский CLI сам форматирует пакет из структурированного ответа. Пояснения
только для черновика в пакеты не попадают. При изменении и удалении
отправляется исходная версия записи в `If-Match`; устаревшая версия
отклоняется. Тело запроса ограничено 1 МиБ. Клиент ждёт ответ три секунды и
не повторяет запрос автоматически. Во встроенном сервере нет аутентификации
и TLS: используй loopback или ограничь доступ доверенной приватной сетью.

## Перенос целого реестра

`buro export <file>` создаёт детерминированный YAML-манифест с правами
`0600`: сведения о пресете, хеш модели, записи и версии. `buro import
<file> [--adopt]` проверяет весь манифест и объявленные ссылки, снимает
копию непустой базы и заменяет записи в одной транзакции. `--adopt` нужен,
если у манифеста другой пресет или версия. Эти команды требуют прямого
доступа к хранилищу. Экспорт содержит частные сведения экземпляра — держи
его в закрытом state. Import нужен для восстановления и миграции модели;
обычные правки проходят через черновик.
