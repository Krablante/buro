# Архитектура

[English](architecture.md) · [Русский](architecture.ru.md) · [README](../README.ru.md)

CLI и HTTP используют общий resolver для поиска, проверки, выдачи, версий и
изменений. CLI ведёт локальный YAML-черновик. Локальный режим открывает SQLite;
клиентский использует HTTP и хранит только настройки и черновик. Сервер
необязателен. Подключения агентов поставляют инструкции; BURO не запускает
модель или индексатор диска.

```text
CLI / локальный draft ─┐
                      ├─ resolver ─ выбранные определения типов ─ SQLite
HTTP-клиенты ──────────┘                               └────────── снимки
```

Запись — одна строка: id, имя, тип, версия и JSON проверенных по схеме полей.
Таблицы для каждого типа не создаются. Отдельные YAML-конфиги собираются в ту
же внутреннюю модель, что и прежние полные пресеты. Guides не меняют хеш
контракта данных. Применённая модель сохраняется в metadata для миграции и
экспорта; это не второй источник редактируемых фактов.

Имена и алиасы используют индекс поиска, принадлежность машинам — индекс
местоположений. Оба производны от основных записей и обновляются в одной
транзакции. Чтение по id не сканирует реестр. Список и поиск выдают только
идентификаторы ограниченными страницами. Контекст показывает до 100 связанных
записей; brief их не загружает. Поиск подстроки может сканировать ключи поиска;
это не семантический поиск по документам.

Изменение получает блокировку записи SQLite, проверяет исходную версию и
ссылки, создаёт согласованный снимок и обновляет запись с индексами. Процесс
последовательно выполняет изменения; разные процессы координирует SQLite.
Вложенные объявленные ссылки тоже проверяются. Неудачная запись сохраняет draft.
Конфликты идентификаторов машин и алиасов проверяются через индекс поиска.
Удаление читает по одной записи только у типов с объявленными ссылками.
Если в модели нет ссылок, проверка удаления не сканирует реестр.

`init` проверяет предлагаемую модель до применения. Известные старые модели
переносят host/path в locations. Несовместимые пользовательские изменения
отклоняются до записи. Изменённые записи получают новые версии. Предпросмотр
проверяет без изменения базы. Запуск сервера проверяет привязку и не перестраивает
все индексы при каждом перезапуске.
Повторный `init` с теми же определениями не меняет базу и резервные копии.
Правка только guides обновляет metadata модели без перестройки записей и индексов.
Предпросмотр использует транзакцию чтения и не получает блокировку записи.

Полное чтение нужно для экспорта, явного администрирования и применения
изменённой модели.
Снимки копируют SQLite перед изменениями: частые записи в большой реестр требуют
дискового I/O. BURO хранит устойчивые сведения, а не поток событий.

Обязанности отражены в исходниках: `schema.js` читает и проверяет определения
и значения; `db.js` ведёт SQLite и производные индексы; `resolver.js` задаёт
правила поиска и изменений. `migration.js` и `registry.js` применяют модели
и переносимые экспорты. CLI и черновик, HTTP и клиент, выдача пакетов и подключение
агентов держат собственные детали интерфейса. Отдельных сервисов для этих частей
нет. Изменение и упаковка описаны в [разработке](development.ru.md).
