# Эксплуатация и восстановление

[English](operations.md) · [Русский](operations.ru.md) · [README](../README.ru.md)

`buro init` создаёт местную память и устанавливает расписание резервных копий.
Настройки и данные находятся вне пакета:

```text
~/.config/buro/config.json
~/.local/share/buro/state/buro/buro.sqlite3
~/.local/share/buro/state/buro/backups/sqlite/{mutation,hourly,daily}/
```

Повторные и одновременные init сохраняют существующую память. Если первый init
завершился ошибкой до применения, устраните причину и повторите команду: оставшуюся
пустую базу можно безопасно инициализировать.

Черновики — закрытые файлы во временных каталогах ОС, каждый со своим путём.
Рядом с исходниками они не хранятся. Очистка временных каталогов может удалить
старые черновики; важные незавершённые правки сохраните отдельно.

## Настройки

Для обычного местного старта конфиг редактировать не нужно. Клиент общей памяти:

```json
{
  "api_url": "http://registry:8765",
  "current_context": "laptop",
  "current_limit": 100
}
```

Наличие api_url выбирает HTTP, отсутствие — SQLite. Клиенты не создают и не
используют запасную местную базу. Имя устройства по умолчанию берётся из короткого
системного hostname. Соответствующая запись host необязательна. Если она есть,
current передаёт её правила, а также список объектов с расположением на устройстве.
Превышение лимита списка явно отмечается в выводе.

`BURO_CONFIG` выбирает файл настроек. Переменные окружения важнее JSON:

| Настройка JSON | Переменная | По умолчанию |
| --- | --- | --- |
| api_url | BURO_API_URL | пусто: прямая SQLite |
| current_context | BURO_CURRENT_CONTEXT | короткий hostname |
| current_limit | BURO_CURRENT_LIMIT | 100, максимум 10000 |
| api_timeout_ms | BURO_API_TIMEOUT_MS | 5000 |
| instance_root | BURO_ROOT | ~/.local/share/buro |
| state_dir | BURO_STATE_DIR | instance_root/state/buro |
| database_path | BURO_DATABASE_PATH | state_dir/buro.sqlite3 |
| backup_dir | BURO_BACKUP_DIR | state_dir/backups/sqlite |
| backup_retention | BURO_BACKUP_RETENTION | 20 снимков перед правками |
| backup_schedule | — | true; false отключает установку расписания |

Действующая модель и тип по умолчанию хранятся в SQLite. Пути пресетов,
type_files, schema_path, mode, central_host и единственный draft_path устарели.
Init переносит сохранённую модель v2 и после успеха удаляет эти настройки.
У прежнего центрального конфига api_url описывал собственный сервер; init
убирает его. У прежнего клиента api_url остаётся адресом общей памяти.
Если клиент v2 использовал только mode/central_host, перед обновлением укажите
api_url прежнего сервера. Init откажется создавать ему местную память.

## Резервные копии

Снимки создаются согласованным SQLite backup API с закрытыми правами. Финальное
имя файл получает только после завершения. Ошибка отменяет правку. Старые снимки
удаляются лишь после успешной новой копии в той же группе. Незавершённые .partial
для восстановления не используются.

| Группа | Что хранится |
| --- | --- |
| hourly | Последние 8 снимков с интервалом не менее 3 часов |
| daily | Последние 8 снимков с интервалом не менее 24 часов |
| mutation | Последние 20 снимков перед правкой записи, типа, импортом или восстановлением; сюда же идут ручные копии |

`buro backup` делает ручной снимок. `buro backup --scheduled` создаёт актуальные
hourly/daily, если подошёл срок, без заполнения пропущенных интервалов. Повторный
init обновляет одно расписание для базы, не создавая дубликатов. Оно устанавливается
только на устройстве с базой. CLI запускается на короткое время; отдельного демона нет.

Linux использует пользовательские таймеры systemd с Persistent=true. macOS —
LaunchAgent с RunAtLoad и интервалом три часа. Windows — пользовательскую задачу
с StartWhenAvailable, выбранным конфигом и путями хранения. Если
планировщик не работает или недоступен, init явно пишет NOT enabled и показывает
команду для ручного расписания. Linux-подключение проверяется на рабочих системах;
установщики macOS и Windows требуют проверки на этих ОС. Выключенное устройство
копий не делает. Persistent в Linux запускает одну актуальную задачу после
включения; RunAtLoad в macOS делает это при входе; Windows догоняет при доступности.
Расписание сохраняет выбранные базу, каталог копий и контекст устройства,
включая настройки, переданные через переменные окружения при init.

В снимке есть записи, определения, удалённые ID, версия BURO и настройки контекста
устройства с базой, независимо от имени клиента, который отправил правку.
Для защиты от поломки диска храните копии на другом устройстве.
Частые записи копируют базу и расходуют I/O и место. BURO подходит для устойчивых
фактов, а не потока событий.

## Экспорт, замена и восстановление

```sh
buro export memory.yaml
buro import memory.yaml --dry-run
buro import memory.yaml
buro restore /absolute/path/to/snapshot.sqlite3 --dry-run
buro restore /absolute/path/to/snapshot.sqlite3
```

Import заменяет всю память: определения, записи и удалённые ID. Просмотр показывает
прежнее и новое количество, а также исчезающие ID — первые 100 и полное число.
Входящий файл проверяется целиком. Даже пустой, но корректный экспорт может
очистить реестр. Перед импортом и восстановлением снимок обязателен. Замена
транзакционная; все прежние черновики после неё отклоняются.

Для восстановления остановите API и других писателей, проверьте выбранный снимок,
восстановите, прочитайте `buro list` и известную запись, затем запустите API.
Восстанавливаются также current_context и current_limit. Пути хранения и настройки
транспорта целевого устройства остаются его собственными, чтобы проверочная копия
не открыла исходную базу. Если запись конфига не удалась, замена базы откатывается.
Для проверки на другом устройстве сначала выполните init с изолированным корнем
данных. Снимки v2 с сохранённой моделью восстанавливаются с тем же однократным
переносом определений.

Тайм-аут клиента не доказывает неудачу записи: сервер мог завершить её после разрыва
связи. Перед повтором прочитайте нужную запись. Неудачный push оставляет черновик.
Несовместимая правка типа сохраняет прежнюю модель доступной для чтения.

| Симптом | Что сделать |
| --- | --- |
| API недоступен | Проверьте api_url и связь с этого устройства; сохраните выбранную общую память. |
| Черновик устарел | Получите свежий и согласуйте нужную правку с текущими значениями. |
| Ошибка резервной копии | Проверьте свободное место и права на backup_dir, затем повторите сохранённый черновик. |
| Нет начального контекста | Проверьте `buro current` в окружении харнесса, повторите connect и перезапустите OpenCode/OpenCodez либо проверьте терминальный hook. |

## Общая память и развёртывание

`buro serve` слушает 127.0.0.1:8765. Адрес и порт меняются через `--host` и `--port`.
Во встроенном сервере нет аутентификации, разграничения прав и TLS. Любой допущенный
клиент может читать и менять память. Ограничивайте доступ сетью, VPN, туннелем или
защищённым HTTPS-прокси. База, экспорты, снимки и обычный HTTP не шифруются самим
BURO. packet:false не ограничивает доступ.

`npm run deploy:live` — необязательная Linux-процедура Politia, а не требование
публичной установки. Она собирает пакет, останавливает центральный API, сохраняет
старый пакет, конфиг и снимок, обновляет и проверяет установленный CLI/API,
затем доставляет тот же пакет доступным клиентам. Недоступные хосты остаются
в списке ожидания; ошибка доступного хоста завершает установку неуспешно.
Сохраняется каталог с контрольной суммой пакета и сведениями для продолжения.
После обновления повторите connect; изменение плагина требует перезапуска агента.

`--dry-run` показывает действия, `--skip-workers` ограничивает установку центральным
устройством. BURO_WORKER_HOSTS задаёт SSH-имена через пробел; иначе используются
ssh_target включённых host-записей. BURO_SOURCE_ROOT выбирает исходники, PACK_DIR —
каталог пакета, BURO_WORKER_PREFIX по умолчанию равен /usr. Местные данные
и центральная база клиентам не синхронизируются.
