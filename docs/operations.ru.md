# Настройки и эксплуатация

[English](operations.md) · [Русский](operations.ru.md) · [README](../README.ru.md)

Локальная работа не требует сервера и ручной настройки. `buro init` создаёт
SQLite и, если файла нет, небольшой config.json с готовыми типами. Изменяемые
данные находятся вне установленного пакета:

```text
~/.config/buro/config.json
~/.local/share/buro/
  BURO_DRAFT.yaml                 # во время правки
  state/buro/buro.sqlite3
  state/buro/backups/sqlite/
```

Настройки программы и YAML-определения типов независимы. Выбор типов описан
в [модели](model.ru.md). Local открывает SQLite, central добавляет HTTP,
client обращается к тому же реестру через HTTP и не хранит копию базы.
Клиенту достаточно:

```json
{
  "api_url": "http://registry:8765",
  "current_context": "worker-a"
}
```

API URL подразумевает client, если mode не задан явно. Имя машины по умолчанию
— короткий hostname. Если имена совпадают, задайте разные `current_context`.
Запись host необязательна: она хранит общие правила машины и существующий корень.

`BURO_CONFIG` выбирает config.json; переменные окружения имеют приоритет над
JSON. `type_files` выбирает готовые имена или YAML-пути, `default_kind` — тип
по умолчанию. Эти два параметра задаются в JSON. Старые полные модели через
`preset` / `schema_path` сохраняются; явный type_files имеет приоритет.

| Ключ JSON | Переменная |
| --- | --- |
| mode | BURO_MODE |
| current_context | BURO_CURRENT_CONTEXT |
| api_url | BURO_API_URL |
| central_host | BURO_CENTRAL_HOST |
| instance_root | BURO_ROOT |
| state_dir | BURO_STATE_DIR |
| database_path | BURO_DATABASE_PATH |
| backup_dir | BURO_BACKUP_DIR |
| backup_retention | BURO_BACKUP_RETENTION |
| draft_path | BURO_DRAFT_PATH |
| preset | BURO_PRESET |
| schema_path | BURO_SCHEMA_PATH |

`buro backup` использует online backup API SQLite. Перед изменениями и
применением модели сохраняется снимок; предпросмотр снимок не создаёт.
По умолчанию остаются последние 20. Копируется вся база: частые изменения
большого реестра расходуют I/O и место. События и разговоры храните отдельно.
Восстановление проверяйте в другом экземпляре через экспорт/импорт или снимок.

При обновлении установите пакет, проверьте `buro init --dry-run`, выполните
`buro init` и обновите подключение агента. Центральный API остановите на время
применения новой модели, затем перезапустите и обновите клиентов. Известные
модели v1 переносятся с сохранением записей. До проверки API и клиентов храните
прежний пакет и снимок. Не восстанавливайте базу, пока в неё идёт запись.

`init`, `backup`, `export`, `import`, `serve` требуют прямого хранилища.
У HTTP нет авторизации и TLS: используйте loopback, доверенную частную сеть
или защищённый proxy. Клиенты не копируют и не открывают центральный SQLite.

## Развёртывание Политии

`npm run deploy:politia` (также `deploy:live`) — операторский Linux workflow,
а не публичный установщик. Он проверяет GIF, делает предпросмотр центральной
миграции, собирает пакет, обновляет центральную установку и API, затем ставит
те же байты на доступные workers. Используются настроенные SSH, sudo и пресет
Политии. Перед использованием вне этой среды прочитайте `scripts/deploy-live.sh`.
Изменение исходников не обновляет работающую установку.

```sh
npm run deploy:politia -- --dry-run
npm run deploy:politia
```

Недоступный worker остаётся pending; ошибка доступного хоста проваливает deploy.
При неполном развёртывании сохраняйте пакет для завершения. Плагины агентов
требуют отдельного обновления и перезапуска процесса.

## Терминальные демонстрации

`npm run demos` пересобирает GIF на двух языках из реального CLI с отдельными
starter-данными. `npm run demos:check` проверяет их по тому же сценарию.
Нужны ffmpeg с ass/palette и DejaVu Sans/Mono. Каталог шрифтов выбирает
`BURO_DEMO_FONTS_DIR`. Рабочая база и черновик оператора не используются.
