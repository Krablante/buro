# Разработка и упаковка

[English](development.md) · [Русский](development.ru.md) · [README](../README.ru.md)

BURO запускается из исходников: транспилятор, сборщик и обязательный сервер
не нужны. Используйте Node.js 24.14 или новее. SQLite входит в Node через
`node:sqlite`; единственная внешняя зависимость программы — `js-yaml`.

```sh
git clone https://github.com/Krablante/buro.git
cd buro
npm ci
node src/cli.js help
```

Отделяйте эксперименты от рабочего реестра. Эти переменные выбирают временный
локальный экземпляр и не заменяют ваши обычные настройки:

```sh
export BURO_CONFIG=/tmp/buro-development/config.json
export BURO_ROOT=/tmp/buro-development/data
export BURO_MODE=local
node src/cli.js init
node src/cli.js draft new example project
# Отредактируйте указанный черновик; добавьте одно важное правило.
node src/cli.js draft diff
node src/cli.js draft push
node src/cli.js example
```

Если в этом каталоге уже есть работа, выберите другой пустой каталог.
На Windows задайте те же переменные через PowerShell `$env:` и используйте
пути Windows. Публичный CLI и файлы подключения поддерживают Windows/macOS;
скрипт развёртывания Политии предназначен для Linux.

## Где что находится

`src/` содержит программу, `types/` — независимые публичные определения,
`presets/` — выбор стартовых типов и полную модель Политии. В `presets/legacy/`
хранятся точные исторические определения для распознавания старых баз и
экспортов. Это данные совместимости, а не ещё одна активная модель.
`integrations/` и `skills/` содержат файлы для `buro connect`; `scripts/` —
развёртывание и генератор терминальных демонстраций. Базы, копии, черновики,
пакеты и материалы аудита находятся вне checkout. Границы компонентов
объясняет [архитектура](architecture.ru.md).

Исправляйте поведение у владельца логики. Проверка данных принадлежит схеме
или resolver, а не отдельной реализации для каждого CLI/API-маршрута.
Интерфейс клиента не должен загружать весь реестр ради вывода одной записи.
Используйте существующие индексы до добавления таблиц или инфраструктуры.

## Проверка изменённого поведения

Проверяйте настоящий интерфейс во временном экземпляре. После правки черновиков
пройдите создание, pull, diff, push и удаление; убедитесь, что неудачный push
сохраняет черновик. После правки модели проверьте совместимое добавление и
несовместимое удаление. Последнее должно оставить данные нетронутыми.
Восстановите экспорт во втором экземпляре. Для изменений HTTP запустите API
из исходников и обратитесь к нему клиентским CLI:

```sh
node src/cli.js serve --port 18765
# Во втором терминале с теми же отдельными config/root:
BURO_MODE=client BURO_API_URL=http://127.0.0.1:18765 node src/cli.js example
```

Проверяйте синтаксис изменённых JS-файлов, `bash -n scripts/deploy-live.sh`
для скрипта развёртывания и `npm audit --omit=dev` для зависимостей.
При работе с большими реестрами указывайте число записей и размер содержимого,
измеряйте одну операцию до и после на одной машине и учитывайте I/O полных
резервных копий. Рабочий реестр оператора не должен быть тестовыми данными.

## Пакет и релиз

Сборка — это `npm pack`. Выберите каталог вне checkout, посмотрите состав
пакета и установите его с отдельным prefix:

```sh
npm pack --dry-run
npm pack --pack-destination /tmp
npm install -g /tmp/buro-<version>.tgz --prefix /tmp/buro-package-check
/tmp/buro-package-check/bin/buro --version
```

Подставьте настоящую версию из `package.json`. Проверьте установленный CLI
с новым отдельным реестром, включая `buro agent` и подключение к временному
профилю клиента. Проверка checkout не доказывает работоспособность пакета.

Публичные пакеты находятся в GitHub Releases. Для релиза нужны совпадающие
версии package.json и lockfile, тег проверенных исходников и проверенный tarball.
Обновляйте установочные URL в обоих README только после появления asset.
Проверьте контрольную сумму скачанного файла. Публикация и развёртывание —
отдельные действия; второе описано в [эксплуатации](operations.ru.md).

## Терминальные демонстрации

`npm run demos` собирает ENG/RU GIF из настоящего CLI в отдельных starter-
экземплярах. `npm run demos:check` пересобирает их и сравнивает байты.
Для такого сравнения используйте одинаковые ffmpeg и шрифты: смена рендерера
может менять пиксели без изменения поведения BURO. При изменении вывода
или раскладки просмотрите готовые кадры.

Нужны ffmpeg с ass/palette и DejaVu Sans/Mono. `BURO_DEMO_FONTS_DIR` выбирает
другой каталог шрифтов. Генератор медиа необязателен для обычной разработки,
упаковки и развёртывания runtime.

## Языки документации

Английская версия использует имя без суффикса; остальные — языковой суффикс:
`README.ru.md`, `docs/model.ru.md` и так далее. Применяйте правило ко всем темам.
Добавление `*.uk.md` или `*.de.md` не требует переноса существующих документов
или изменения программы. Ссылки языков в шапках и таблица тем README должны
соответствовать доступным переводам.

README объясняет продукт и первый запуск. Модель, агенты, черновики, интерфейсы,
архитектура, эксплуатация и разработка отвечают каждый за свою тему.
При изменении поведения обновляйте связанные переводы вместе. Совпадение смысла
важнее буквального перевода. Новый язык сохраняет те же смысловые категории.
Переводы терминальных демонстраций находятся в объекте `translations` генератора.
