# Разработка и выпуски

[English](development.md) · [Русский](development.ru.md) · [README](../README.ru.md)

Нужен Node.js 24.14+. SQLite входит в Node; единственная рабочая зависимость —
js-yaml. Для местной работы не нужны сборка и отдельный процесс базы данных.

```sh
npm ci
npm test
node src/cli.js help
npm pack --pack-destination /absolute/path/to/artifacts
```

Для изолированной памяти выберите BURO_CONFIG и BURO_ROOT вне исходников.
Укажите backup_schedule:false в её конфиге, если настоящий таймер ОС не нужен.
Не направляйте экспериментальный код на рабочую базу. Проверки создают временные
установки и покрывают сохранность, конфликты, ссылки, сбои копирования, замену,
восстановление, файловые черновики CLI и настройки подключений.

## Обязанности частей

CLI и HTTP обращаются к одному resolver. Просмотр и push используют applyChange;
push повторяет проверку после получения блокировки записи SQLite. Schema отвечает
за определения полей и нормализацию. DB — за исходные записи, производные индексы,
транзакции и согласованные снимки. Registry — за полный экспорт, импорт и
восстановление. Migration — узкий однократный перенос сохранённой модели v2;
старые пресеты и поведение команд он не поддерживает.

Действующая модель находится в метаданных SQLite. У каждого типа своя версия.
У записей независимые версии; поколение реестра меняется после замены и
восстановления. Метаданные черновика содержат исходное поколение, версию записи
и версии типов. При правке записи проверяются лишь нужные типы, поэтому
изменение постороннего типа не делает её черновик устаревшим.

Запись — одна строка таблицы: ID, имя, kind, JSON-значения и версия. Удалённые ID
остаются в retired_ids. Нормализованные имена и псевдонимы индексируются; список
устройства строится по производному индексу locations. Они обновляются в одной
транзакции с исходными данными. Чтение точного ID не сканирует память. List/search
получают ограниченный список кратких сведений. Поиск подстроки может сканировать
ключи индекса, но не тела записей; семантического поиска нет. Большие offset
проходят пропущенные элементы индекса. Current может сортировать подходящие краткие
записи до применения лимита вывода. Изменение формата типа последовательно
проверяет его записи перед принятием; смена подписи и пояснений записи не сканирует.
Обычная правка не перечисляет память, кроме нужной проверки
входящих ref. Полный экспорт/импорт соразмерен размеру памяти и держит весь
переносимый документ в оперативной памяти.

Снимок создаётся перед изменением исходных данных, внутри транзакции, которая
не пускает других писателей. SQLite координирует процессы; resolver ставит записи
одного сервера в очередь. Определения читаются из принятой модели, поэтому
неверная правка не перекрывает рабочее чтение. HTTP-сервер получает свежие
определения без перезапуска после правки типа. Второго реестра, клиентских копий
базы, RAG-хранилища и фоновой нейросети нет.

Каждая содержательная правка также копирует всю базу для обязательного снимка.
Это основная стоимость, которая растёт с объёмом содержимого; ограниченный вывод
запросов не делает запись операцией постоянной стоимости. Частые логи и большие
двоичные данные храните вне BURO, оставляя в нём полезные факты и расположения.

## HTTP

`buro serve` предоставляет следующие JSON-маршруты. Они заменяют транспорт v2;
обновляйте клиентов вместе с сервером.

| Метод и путь | Ответ / назначение |
| --- | --- |
| GET /health | Состояние хранилища и число записей |
| GET /definitions | Принятая схема и поколение реестра |
| GET /current | Запись устройства, список объектов, лимит, признак усечения |
| GET /records | Страница кратких сведений; kind, limit, offset, query; full=1 добавляет содержимое для пакетного чтения |
| GET /records/:id-or-name | Полная запись, включая скрытые из packet поля |
| GET /records/:id?exact=1 | Только точный ID |
| GET /records/:id-or-name?packet=1 | Запись для форматированного вывода |
| POST /drafts/preview | Проверка черновика, значения до и после |
| POST /drafts/push | Повторная проверка, снимок, применение |

Запросы могут содержать current_context и current_limit. Тело POST —
`{metadata, value}`: __buro из YAML и остальные поля; при удалении value:null.
Оба маршрута требуют метаданные версий и поколения v3. Конфликт возвращает
HTTP 409. JSON ограничен 1 МиБ. Прямых непроверяемых PUT/DELETE для записей нет.
В API отсутствуют аутентификация и TLS; ограничения доступа описаны в эксплуатации.

## Языки документации

Английская версия использует имя Markdown-файла без суффикса. Переводы получают
то же имя с кодом языка: например, `model.ru.md` или `model.uk.md`. Обновляйте
языковые ссылки каждого руководства и таблицу навигации README. Новый язык не
требует изменения программы. Передавайте те же темы и поведение
естественным языком. Пояснения типов и ресурсы подключений — инструкции, которыми
агенты пользуются напрямую; сохраняйте их согласованность с руководствами для людей.

### Публичные руководства в PDF

[guide.md](guide.md) и [guide.ru.md](guide.ru.md) — редактируемые исходники
отдельных [английского PDF](guide.pdf) и [русского PDF](guide.ru.pdf). У каждого
файла свои обложка, оглавление, закладки и нумерация страниц на его языке.
Они последовательно объясняют продукт; тематические руководства остаются
подробным справочником. При изменении описанного поведения обновляйте оба текста
и пересобирайте оба PDF в той же правке.

Для сборки нужны Python 3.11+, [uv](https://docs.astral.sh/uv/getting-started/installation/),
FreeSans и DejaVu Sans Mono. В Debian/Ubuntu шрифты устанавливаются пакетами
`fonts-freefont-ttf` и `fonts-dejavu-core`. Если шрифты лежат иначе, задайте
BURO_PDF_FONTS_DIR — каталог с FreeSans.ttf, FreeSansBold.ttf, FreeSansOblique.ttf
и DejaVuSansMono.ttf. Версии Python-зависимостей закреплены в скрипте; uv ставит
их изолированно. Самому BURO они не нужны.

```sh
uv run scripts/generate-guide.py
uv run scripts/generate-guide.py --check
```

Check пересобирает документы в памяти и сравнивает байты с каждым сохранённым PDF.
ID и порядок глав должны совпадать между языками, версия в примере установки —
с версией пакета. Номера страниц, оглавление, закладки и подписи версии собираются
автоматически. Сохраняйте якоря глав. Для сборки отдельного PDF нового перевода
добавьте его и тексты оглавления в LANGUAGES рендерера. Поддерживаются абзацы,
заголовки, таблицы, списки, цитаты и блоки кода из исходников; неподдерживаемая
разметка вызывает явную ошибку.

После правок отрисуйте оба PDF через Poppler вне исходников и просмотрите страницы:
ссылки оглавления, длинные команды, таблицы и разрывы страниц. Сохраняйте Markdown
и оба PDF одним коммитом. Обновление только руководств не требует перезапуска сервиса
или выпуска рабочей версии.

## Пакет и выпуск

Один пакет содержит CLI, сервер, три готовых определения, skill агента, блок
для ручной вставки в промпт, плагин, обработчик hooks, документацию и необязательные
операторские скрипты. Проверки, частные факты, местные базы, временные файлы
и зависимости из исходников исключены списком публикуемых файлов. Операторские
записи не попадают в публичный репозиторий или пакет.

Версия пакета и lockfile обновляются вместе. Перед выпуском пройдите проверки,
настоящую установку пакета, новый старт, обновление и восстановление копии.
Актуализируйте обе README и затронутые руководства. Коммит и тег создаются после
проверки результата. Tgz публикуется во вложениях соответствующего GitHub-релиза.
Правка исходников сама по себе не обновляет установленный CLI и рабочие процессы.

`npm run demos` создаёт двуязычные GIF для README из реальных сценариев CLI
во временной памяти. Нужны ffmpeg с libass и DejaVu Sans/Mono. `npm run demos:check`
проверяет их содержимое. Если шрифты лежат иначе, задайте BURO_DEMO_FONTS_DIR.
Этот инструмент независим от рабочей установки. После изменения CLI или
демонстрации проверяйте сами кадры, особенно длинные строки и русский текст.
