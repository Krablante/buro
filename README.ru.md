## Зачем BURO

Вы возвращаетесь к проекту сайта через неделю. Агенту нужно знать, где лежат
исходники, на каком сервере работает сайт, что вы решили в прошлый раз и какие
изменения требуют согласования. BURO хранит эти сведения в записи, которую
агент может открыть, когда вы назовёте проект.

**У каждого рабочего объекта своя память.** Проекты, сервисы, устройства, книги
или исследования могут иметь собственные записи. Память существует независимо
от папок с проектами и может быть общей для нескольких устройств. Агент читает
нужные для задачи записи и поддерживает полезные сведения по мере работы.

## Как устроена память

У записи есть **тип**, а у типа — определения полей, их форматов и назначения.
Благодаря этому агент знает, где искать нужный факт и куда записывать новый.

Например, запись о сайте может выглядеть так:

```yaml
id: my-site
name: Мой сайт
kind: project
summary: Личный сайт со статьями и заметками.
locations:
  - host: laptop
    path: /work/my-site
important:
  - Согласовать со мной публикацию.
avoid:
  - Не хранить рабочие данные в исходниках.
read_first:
  - README.md
```

У коробочных типов обязательны только `id`, `name` и `kind`. Начните с тех
сведений, которые действительно нужны.

<details>
<summary><strong>Что можно запомнить в записи?</strong></summary>

| Поле | Что в нём хранится |
| --- | --- |
| `summary` | Что это за объект и зачем он существует. |
| `important` | Принятые решения, требования и условия согласования. |
| `avoid` | То, чего агенту делать не следует. |
| `locations` | Исходники, рабочие установки, адреса и их устройства. |
| `read_first` | Документы, которые нужно прочитать перед работой. |
| `related` | Связанные объекты, документы и полезные ссылки. |
| `notes` | Дополнительные устойчивые сведения. |
| `aliases` | Другие названия того же объекта. |

У типов могут быть и собственные поля. Пояснения к полям подсказывают агенту,
как их использовать.

</details>

В комплекте три типа:

| Тип | Для чего |
| --- | --- |
| `project` | Продукты и самостоятельные дела: сайт, приложение, книга. |
| `service` | Технические компоненты рабочей среды. |
| `host` | Компьютеры и серверы. |

**Ваша память может использовать собственные типы.** Можно создать `book`,
`research` или `person` с нужными полями. Определения хранятся в базе и
редактируются через тот же проверяемый процесс, что и записи. Начать можно с
`buro types new book`; подробности — в [руководстве по типам](docs/model.ru.md).

## Как это работает с агентом

1. **Перед работой — дать агенту контекст.** Skill объясняет, как читать и вести
   память. Подключение сессии запускает `buro current`: передаёт запись текущего
   устройства, если она есть, и ограниченный список связанных объектов.
   Готовый блок системного промпта помогает держать основные правила в каждом запросе.
2. **Во время работы — открыть нужные записи.** Когда вы просите продолжить
   проект, агент обращается к BURO через терминал и читает его сведения, решения
   и ограничения. При необходимости открывает связанные записи.
3. **После работы — сохранить то, что пригодится дальше.** По умолчанию skill
   поручает агенту записывать полезные подтверждённые решения, новые факты и
   исправления. Каждая правка проходит через YAML-черновик, diff и push.
   Если полезных изменений нет, записывать ничего не нужно. Это правило можно изменить.

BURO даёт структуру, инструменты и инструкции. **Качество автономной памяти
по-прежнему зависит от агента:** что он решит запомнить, как проверит сведения
и заметит ли, что сохранённые факты устарели.

## Начать работу

Нужен **Node.js 24.14 или новее**.

```sh
npm install -g \
  https://github.com/Krablante/buro/releases/download/v3.1.0/buro-3.1.0.tgz
buro init
buro connect opencodez
```

Вместо `opencodez` укажите `opencode`, `codex` или `claude`, если используете
другой харнесс. Connect устанавливает **skill и подключение контекста сессии**
из того же пакета.

После подключения:

- **OpenCode / OpenCodez:** перезапустите приложение, чтобы загрузить плагин.
- **Codex:** проверьте и разрешите SessionStart hook через `/hooks`, при
  необходимости включите hooks, затем начните новую сессию.
- **Claude Code:** начните новую сессию с включёнными SessionStart hooks.

Для OpenCodez рекомендуется использовать и [skill](skills/buro/SKILL.md), и
[блок системного промпта](skills/buro/system-prompt.md): промпт постоянно
напоминает основные правила, а skill объясняет рабочий процесс. Добавьте блок
в настройки сами — **connect не редактирует системный промпт**.

Теперь можно попросить агента использовать BURO для проекта и поддерживать его
память. Чтобы открыть запись самостоятельно, выполните `buro my-site`;
`buro help` показывает команды и действующие определения вашей памяти.

![Работающий BURO: создать черновик, проверить diff, сохранить и прочитать запись](assets/demo-ru.gif)

<details>
<summary><strong>Другой профиль, другой агент или ручное редактирование</strong></summary>

Выбрать профиль явно:

```sh
buro connect opencodez --path /path/to/profile
```

Для харнесса без готового подключения можно добавить инструкцию в файл:

```sh
buro connect file --path /path/to/AGENTS.md
```

Это подключение добавляет инструкции; автоматическая загрузка контекста
настраивается отдельно. Подробнее — в [подключении агентов](docs/agents.ru.md).

Память можно редактировать и самостоятельно:

```sh
buro draft new my-site project
# Отредактируйте напечатанный YAML-файл. Сохраните метаданные __buro.
buro draft diff /tmp/buro-draft-EXAMPLE/change.yaml
buro draft push /tmp/buro-draft-EXAMPLE/change.yaml
```

В diff и push нужен настоящий путь из вывода. Для существующей записи начните с
`buro draft pull my-site`. Неудачный push сохраняет черновик; при конфликтующей
правке потребуется свежий. Подробнее — в [записях и типах](docs/model.ru.md).

</details>

### Обновление

```sh
buro update --check
buro update
```

Update устанавливает последний стабильный релиз GitHub на этом устройстве,
применяет совместимые обновления коробочных типов и обновляет уже подключённые
skill, плагины и hooks. Свои типы сохраняются. После обновления перезапустите
работающих агентов и API BURO. Версии до 3.1 сначала обновляются через npm;
для старых нестандартных профилей один раз повторите connect, чтобы запомнить
путь. Подробнее — в [обновлении BURO](docs/operations.ru.md#обновление-buro).

## Хранение и сохранность

**Для местной работы достаточно CLI и файла SQLite.** Для общей памяти запустите
HTTP-сервер BURO на устройстве с базой и направьте к нему клиентов. Копий базы
у клиентов нет. Исходники программы, записи и настройки находятся отдельно,
поэтому обновление пакета сохраняет вашу память.

Правки проверяются на допустимые поля, форматы, ссылки и конфликты версий.
Перед каждой правкой обязателен успешный снимок; местный init также настраивает
расписание резервных копий. BURO не запускает модель и не читает чаты в фоне.
Достоверность сведений проверяете вы и агент.

Общий сервер рассчитан на доверенный доступ через частную сеть, VPN, туннель или
защищённый HTTPS-прокси. Встроенных аутентификации и TLS нет; база и копии не
шифруются. Подробнее — в [эксплуатации и восстановлении](docs/operations.ru.md).
