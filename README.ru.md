<h1 align="center">BURO</h1>

<p align="center"><strong>Знай, где находится работа.</strong></p>

<p align="center">Типизированный реестр проектов, сервисов, хостов и правил работы с ними.<br>Одна команда даёт человеку и агенту одинаковые записанные сведения на любой машине с Node.js.</p>

<p align="center"><a href="README.md">English</a> · <a href="README.ru.md"><strong>Русский</strong></a></p>

BURO собирает адресные сведения, ради которых обычно плодят файлы с правилами
для агентов или поисковые пайплайны: владельца, путь, стартовые документы и
эксплуатационные ограничения. Пресет задаёт поля, SQLite хранит записи, а CLI
выводит пакет нужной сущности. Для нескольких машин есть необязательный HTTP
сервер: клиентам не нужны копии базы.

BURO проверяет структуру и объявленные ссылки. **Он не доказывает, что запись
верна и всё ещё актуальна.** Сверяй факты с источниками и исправляй их, когда
система меняется. Подробные инструкции остаются в документации самого проекта;
реестр указывает, что читать.

## Как это выглядит

```text
$ buro my-service
BURO Entity: service:my-service
Name: My service
Context: workstation (current)

LOCATION:
  host: workstation
  path: /workspace/services/my-service

READ_FIRST:
  read_first:
    - README.md
```

Поля и заголовки зависят от пресета. Агенту достаточно постоянной инструкции:
«Сначала спроси BURO о нужной сущности, прочитай указанные документы, а
противоречия проверь по фактическому состоянию». `buro current` показывает
настроенный хост и связанные сущности; `buro list [kind]` помогает найти
неизвестный идентификатор.

Обычная правка проходит через один проверяемый черновик:

```text
buro draft pull my-service     # также: draft new <id> [kind], draft delete <id>
# Отредактируй YAML-файл по пути, напечатанному командой.
buro draft diff
buro draft push
```

Черновик хранит исходную версию записи. Конфликтующая правка отклоняется;
перед успешной записью создаётся резервная копия SQLite. GIF собран из
настоящего CLI в одноразовом экземпляре:

![Инициализация, черновик, diff, push и current в одноразовом starter-экземпляре](assets/demo-ru.gif)

## Начало работы

Нужен **Node.js 24.14+**. CLI работает на платформах, поддерживаемых Node.js
и встроенным SQLite; скрипт развёртывания Politia предназначен для его
операторской установки на Linux.

```sh
git clone https://github.com/Krablante/buro.git
cd buro
npm install -g .
buro init
```

`buro init` печатает точную команду `buro draft new <hostname> host` для
текущей машины. Выполни её, открой черновик по указанному командой пути,
заполни обязательные `root` и `summary`, затем выполни `buro draft diff`,
`buro draft push` и `buro current`. Для разработки достаточно `npm install` в
репозитории и `node src/cli.js` без глобальной установки.

По умолчанию экземпляр находится в `~/.local/share/buro` (там же база,
копии и текущий черновик), конфигурация — в `~/.config/buro/config.json`.
Пути можно изменить. Полная таблица настроек — в разделе
[«Эксплуатация»](docs/operations.ru.md).

Встроенный пресет [`starter`](presets/starter.yaml) описывает хосты, проекты,
сервисы и документы. Собственный словарь задаётся в YAML без изменения
движка. Активную модель показывает `buro schema [kind]`. Пресет
[`politia`](presets/politia.yaml) — пример более крупной рабочей модели;
частные записи Politia в пакет не входят.

## Участие

Объясни проблему, новое поведение и выполненную проверку. Не добавляй частные
записи реестра в публичные пресеты, примеры и артефакты. Существенное изменение
лучше сначала обсудить в issue.
