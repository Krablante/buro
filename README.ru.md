<h1 align="center">BURO</h1>

<p align="center"><strong>Типизированное хранилище знаний для AI-агентов.</strong></p>

<p align="center">Типы записей и поля задаются YAML-конфигами.<br>Замена разросшимся AGENTS.md и RAG для постоянного контекста агента.</p>

<p align="center"><a href="README.md">🇬🇧 English</a> · <a href="README.ru.md"><strong>🇷🇺 Русский</strong></a></p>

BURO хранит знания в типизированных записях. Вы определяете свои типы, поля и
подсказки обычными YAML-конфигами: правила, решения, ограничения, описания систем
и любые другие сведения, которые агенту нужно помнить между сессиями.

Вместо загрузки разросшегося AGENTS.md или сборки контекста из найденных RAG
фрагментов агент запрашивает нужную запись по имени или идентификатору.
Он получает целую запись с понятными полями и пояснениями к ним. Знания хранятся
в SQLite; изменения проходят через YAML-черновик, diff и проверку ревизии.

## Установить и подключить

Нужен **Node.js 24.14+**. Установите пакет релиза:

```sh
npm install -g https://github.com/Krablante/buro/releases/download/v2.0.1/buro-2.0.1.tgz
buro init
buro connect opencodez
```

Для других клиентов выберите `opencode`, `codex` или `claude`. После установки
плагина перезапустите OpenCode/OpenCodez; в остальных клиентах начните новую
сессию. Для другого агента с терминалом используйте
`buro connect file --path /путь/к/AGENTS.md`. Для самостоятельного редактирования
System prompt скопируйте вывод `buro agent`; подробные правила выдаёт
`buro agent --full`. Подключение сохраняет посторонние инструкции и создаёт
резервные копии изменяемых файлов.

Затем скажите агенту: «Запомни: публиковать мой сайт можно только после моего
разрешения». BURO поставляет инструкции и skill; агенту нужен доступ к терминалу
и разрешение поддерживать записи. BURO не запускает модель, не сканирует диск
и не читает разговоры в фоне.

Работа с исходниками описана в [руководстве разработчика](docs/development.ru.md).

## Полезная запись может быть короткой

```yaml
id: my-site
name: Мой сайт
kind: project
important:
  - Перед публикацией спросить меня.
```

Готовые типы: `project`, `service`, `host`, `item`. Содержательные поля
необязательны. Запись можно получить по имени или алиасу; при неоднозначности
BURO предлагает выбрать id. `buro search сайт` помогает найти нужное без
загрузки всего реестра.
Запись с именем и одним важным правилом уже полезна. BURO проверяет структуру
и конфликты правок; достоверность сведений проверяете вы и агент.

```sh
buro draft new my-site project  # либо draft pull / draft delete
# Отредактируйте файл, указанный командой.
buro draft diff
buro draft push
buro my-site
buro types project
```

У объекта может быть несколько `locations`: машина, путь, URL и назначение.
Для пути без машины при сохранении записывается текущая машина клиента; это
добавление видно в diff. Исходники и рабочая версия могут находиться в разных
местах. Существующие правила папок хранятся как сведения в записях.
Общий корень, геометрия папок и запись хоста не обязательны.

## Настраивайте только то, что хотите изменить

Настройки программы находятся в `~/.config/buro/config.json`. Определения типов
— отдельные самодостаточные YAML-файлы. Готовые определения работают без их правки.

```json
{
  "type_files": ["project", "service", "host", "item"]
}
```

Команда `buro types copy project /путь/my-project.yaml` копирует готовое
определение. Замените `"project"` в `type_files` путём к этому файлу.
Разные типы могут по-разному определять одноимённые поля. Скрытого объединения
и наследования нет: у каждого типа одно выбранное определение.

Проверяйте изменения через `buro init --dry-run`, применяйте через `buro init`.
BURO сначала проверяет существующие данные. Удаление заполненного поля или типа
отклоняется без потери данных. Известные записи v1 с `host/path` переносятся в
`locations`; прежний тип `document` стартовой модели становится `item`.
Перед применением создаётся резервная копия.

Необязательный HTTP-сервер предоставляет один реестр нескольким машинам.
Локальная работа сервера не требует. Встроенный сервер не содержит авторизации
и TLS: используйте loopback, доверенную частную сеть или защищённый proxy.

Храните постоянные знания один раз и запрашивайте их по мере работы.
Соглашения о коде, правила эксплуатации и принятые решения получают собственные
поля и типы. Через `read_first` запись связывается с подробными руководствами
и исходниками.
